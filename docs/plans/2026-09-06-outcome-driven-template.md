# Deliver outcomes through the template

## Cold-start summary

The maintainer asked this task to turn the template review into improvements,
not another collection of evidence. The requested result is a template that
directs agents toward the user's complete outcome, catches differences between
promised and delivered effects, continues authorized work without phase
approvals, and requires less irrelevant startup reading.

Baseline: `b0e5a8196fc529cb38da76d29d1d00c06e128403`. The existing checker has
111 passing fixtures. The root agent entrypoint is 14,512 bytes. The preceding
[review](../evidence/2026-09-06-template-review.md) is historical evidence, not
new authority. Its untracked files must be preserved.

## Risk and authority

High-risk: changing reusable completion and execution rules can affect future
product decisions. Human authority, authorization boundaries, independent
review requirements, adoption scope, and template profiles remain governed by
their existing owners. Independent design and final review are required by
the agent execution contract. Neither review requires a new user approval for
an engineering choice already within this task.

The maintainer's September 6 feedback supersedes the fixed seven-phase method
where it conflicts with outcome-oriented, continuous authorized delivery.
Reconcile the owning contracts before changing their templates or checker.
This task does not implement a browser extension, enable autonomous portfolio
work, configure commercial harnesses, or claim measured agent effectiveness.

## Complete end state and affected owners

- Development discipline: preserve original intent separately from its accepted
  interpretation; verify functional and activated nonfunctional outcomes in
  both directions, including identity, count, timing, and failure. Choose the
  smallest credible observation for each claim. Improve recurring failure
  mechanisms at their owner and retire redundant reminders.
- Governance boundary and agent execution: accepted authorization persists
  through internal checkpoints; stop only an affected path for a real newly
  exposed decision or blocker. Replace mandatory phases with dependency order
  and claim-specific verification; retain required high-risk reviews.
- Documentation authority map and agent execution: task-relevant sections form
  the working context; memory and handoffs are derived context. Delegation, if
  used, carries bounded scope and returns verifiable results to an integrating
  parent. Do not require a new runtime, registry, or per-task bureaucracy.
- AGENTS and contributor projections: lead with the requested observable
  outcome, preserve epistemic/authority/ownership discipline, and route domain
  details instead of repeating them. Reconcile changed owners' guide projections.
- Existing contract, service, execution, handoff, verification, evaluation, and
  issue templates: make these rules usable in the documents adopters copy.
  Include a worked three-script check example in the operation guide with
  explicit illustrative assumptions and no claim of a provider-safe rate.
- Documentation harness: stop shipping legacy invariant codes in new contract
  scaffolds. A narrow syntax guard protects this already-adopted rule; it must
  not pretend to determine whether a product meets its user's goal.

## Execution and verification

Reconcile contracts and independent design findings, add failure fixtures for
the template syntax defect, implement the complete linked change, then run
the focused fixtures, full suite, and normal/strict repository checks. Review
the resulting template as an adopter: start from a user request and inspect
what each copied form asks the agent to do. Fresh-context final review checks
user intent, consistency, maintenance cost, and missing outcome coverage.

| Claim | Verification | Limitation |
|---|---|---|
| New scaffolds use addressable plain-language invariants | Reject coded heading and bullet variants; accept plain headings and legacy history | Syntax only |
| Authorized delivery has no phase approval ritual | Trace root, owning contracts, plans, and operation guide together | Review, not a live agent evaluation |
| Acceptance considers missing, extra, excessive, and suppressed effects | Inspect copied forms and the worked browser-check example | No extension or provider traffic is run |
| Entry routes required context without duplicating domains | Compare entrypoint bytes, links, and reachable owner sections | Size is not measured behavioral effectiveness |
| Existing adoption and checker behavior is preserved | Full fixture suite and both checker modes | Does not certify commercial harness compatibility |

## Coordination

Root owns all repository edits. Independent reviewers are read-only and receive
this scope, relevant current authority, proposed changes, and baseline facts;
they do not receive the implementer's reasoning history. Shared-surface changes
are announced here and files are reread before final integration.

## Progress and closure

- Design review: independent context `/root/design_review`, supplied this plan,
  governing contracts, and template baseline; no implementation reasoning trace.
  Its system, user, and maintenance lenses found three necessary refinements:
  cross-operation frequency/freshness, original request in reviewer inputs, and
  removal of the remaining mandatory ten-step ordering. Root synthesis accepted
  all three, plus retaining applicable exceptions in reduced context. No new
  human-owned decision arose. Original wording was added where interpretation
  matters because the reviewer initially had only renderings. This was a design
  review of an evolving proposal, not final behavioral verification.
- Shared surfaces: root reconciled the four owning contracts, adoption method,
  document map, entrypoints, guides, selected templates, template inventory, and
  the scaffold guard. No other workstream has write ownership.
- Implementation and regression: new missing-heading and coded-variant fixtures
  failed before the checker change (exit zero on invalid scaffolds), then
  passed after implementation. The final full suite passed 114 tests in 15.281
  seconds with Python 3.14.2. Normal and strict checker runs passed with 27
  canonical documents and 15 selected templates. `git diff --check` passed.
- Fresh-context completion evaluation: `/root/completion_review` reviewed the
  current diff, original request excerpts, accepted plan, owning contracts,
  copied templates, and latest announced edits without producing or editing
  the change. It found no material issue within the static template scope
  (high confidence), independently ran the strict checker and whitespace check,
  and identified live agent behavior, extension behavior, and provider traffic
  as unverified. The full fixture result was supplied by root.
- Observed entrypoint result: `AGENTS.md` is 6,608 bytes versus 14,512 at the
  baseline, a 54.5% reduction. Relevant domain owners, adoption ranking,
  exceptions, and risk routes remain linked. This is a size and routing
  observation, not a measurement of an agent's actual startup context.
- Completion: the reusable template change is implemented and reviewed in the
  working tree based on the baseline revision above; no commit or deployment
  was performed. Current owners and guide projections are reconciled. This plan
  is completed and leaves the active task context; original research remains
  historical and is not a new startup dependency.
- Behavioral adoption effectiveness remains partial; this task closes the
  template change, not the existing real-project adoption review promise.
