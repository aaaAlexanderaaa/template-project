# Independent judgment and progress across autonomous wakes

## Cold-start summary

The maintainer authorized refining the discipline after actual autonomous use
showed repeated local completion without adequate progress toward the original
purpose. The requested change requires fresh, open-ended challenge of direction,
comparison with the strongest alternative use of effort, and meaningful progress
across wakes. General mechanisms belong here; personal context remains private.

Baseline: `203115d1dff37e968def0edce5765b328faa9b86` plus the existing uncommitted
onboarding, design-method and calibration refinements. Those edits are preserved.
An isolated copy includes that complete starting state; this change is reviewed
and applied as a separate patch. No running charter or schedule is amended.

## Authority, scope, and complete end state

The current request authorizes material documentation work at the existing
autonomy and governance owners, their execution route, templates and guidance.
It does not authorize expansion of any adopter's permissions or a new scheduler.

The resulting discipline separates fresh judgment from execution continuity,
requires finite review bounds and evidence of actual dispatch, compares real
candidate work, and carries worthwhile efforts across wakes. A missing review
or consequential unresolved finding prevents affected expansion. Adoption can
distinguish a written rule from an exercised runtime control.

## Baseline and gap

- The previous autonomy rule allowed one context to alternate execution and
  review. Direction could wait for an empty backlog or an exceptional trigger.
- Records of approved work and completed checks could accumulate without a
  baseline comparison of value, cost, or human intervention.
- Work selection lacked a required explanation of the strongest alternative
  and of how candidate coverage was established.
- Changing execution state needed an explicit boundary from issuer-owned
  authorization, so normal strategy changes do not require charter edits.

## Execution and coordination

1. Reconcile the normative owners and affected entry paths and templates.
2. Obtain a fresh, read-only challenge of the historical experiment using the
   agreed purpose, and a separate fresh review of this delivery. Neither worker
   receives the implementer's reasoning before forming its first judgment.
3. Resolve consequential findings and independently recheck the corrections.
4. Run the required repository suite and strict checker; inspect the complete
   added public diff and apply only the reviewed patch to the source tree.

Only the implementer writes public delivery files. Reviewers write private
reports and may inspect artifacts; they do not alter the source experiment or
its automation. No runtime verification is inferred from their reading work.

## Risks and proportionality

This is a material documentation change. It does not implement privilege or
isolation controls. Its main risks are false confidence in unenforced prose,
review becoming unbounded ceremony, and moving normal execution choices back
to the owner. Review is periodic or evidence-triggered, candidate comparison
is retained across mechanical steps, and affected-scope containment permits
unaffected work. A supported no-findings result is valid. Reverting this patch
restores the baseline without discarding prior edits.

## Verification and completion

The [evidence record](../evidence/2026-09-27-autonomous-progress-review.md)
records the completed document review, correction recheck and repository
validation: 118 tests (117 passed, one optional runtime check skipped), plus
38 canonical documents and 16 templates passing strict validation. The public
patch contains no personal profile, private source location or raw quotation.
Earlier working-tree changes are included in the validation baseline and remain
outside this patch. Multi-epoch behavioral effectiveness remains unverified;
the existing first-party evidence promise is unchanged.
