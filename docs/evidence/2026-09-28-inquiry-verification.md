# Research and information access: implementation verification

## Claim and limits

This record checks the portable rules, reading routes, and fresh consumer use
implemented by the [plan](../plans/2026-09-28-research-and-information-access.md).
The original purpose includes discovering useful evidence, avoiding premature
stories and repeated access exploration, and loading methods by need. The
reported experience brief is one input, not the sole specification.

Baseline is `50e5e96` plus the earlier assessment. Root owns implementation;
consumer contexts receive public task inputs and current instructions, without
the parent's reasoning or private sources. No controlled before/after model
comparison is claimed. A successful bounded trial demonstrates that occurrence,
not broad behavioral improvement, typical cost savings, or production adoption.

It contains actual observations, not a universal tool recommendation.

  capability. A prior retrieval failure in the earlier discussion is not a
  permanent block on another route.
- Ownership: this evidence record owns this trial observation, not an adopter's
  general method store. Fresh-task reuse will be recorded below only if observed.

## Consumer assignments and budgets

Two read-only fresh contexts ran under the existing consumer-verification
requirement. Each receives the original purpose in public paraphrase, the new
guide routes, a concrete task, and at most six web calls. They may inspect
applicable local owners. No private context, other repository, writes, or new
subagents are authorized. Calls and known limits are returned with results.

1. **Research:** assess whether the STORM unique-reference result justifies a
   claim of improved factual reliability from diverse questioning. Inspect
   primary evidence and pursue a relevant additional avenue when useful;
   return a supported answer, source relationships, unresolved gaps, and the
   stopping reason. Also examine a supplied fictional repeated-source and
   simulated-reader countercase, clearly labeling its evidence class.
2. **Access:** use this permitted locator to obtain the MMR paper's precise
   reranking criterion and parameter behavior. Inspect the needed observation,
   recover from the text-extraction limit if possible, and return a reusable
   update. Also answer a simple source-metadata lookup without inventing a
   full research task, and describe the response if a previously working route
   later becomes unavailable. The last condition is hypothetical, not a
   measured outage.

Both return their first judgment on whether the instructions were usable and
any consequential defect in the guide or route. The research assignment's
scope is a bounded public-source question, not a comprehensive field review.

## Results

### Research consumer

`/root/research_method_consumer` received the public purpose, guide route,
STORM starting source, and concrete question. It did not read the assessment,
parent reasoning, or existing research reports. It returned its first judgment
with no consequential usability finding.

It inspected [STORM](https://arxiv.org/html/2402.14207v2), followed the paper's
reference to [ALCE](https://aclanthology.org/2023.emnlp-main.398.pdf), and separated
reference breadth from factual reliability. It compared the reference-count
ablation with the separate human verifiability evaluation; that evaluation did
not establish improved reliability. It identified ALCE as a metric dependency,
not an independent replication. Root checked the new ALCE source's separate
correctness and citation-quality measures against the returned interpretation.

The consumer reported four web calls: four opens, two in-page finds, and one
link click, with zero search-engine queries. Targeted reads recovered from a
truncated output and an unhelpful landing page. It stopped because the bounded
inference was resolved, not because the field had been exhaustively surveyed.
It answered a direct question about Table 5 from the same source without a
new research workflow. In the synthetic cases it distinguished one underlying
dataset from five interpretations, and simulated confusion from observed
human difficulty. Those cases are instruction-use evidence, not user research.

### Access consumer

`/root/access_method_consumer` received the public purpose, access guide, and
permitted method locator. It read the note before accessing the source and
returned no consequential guide or route defect. It obtained title, authors,
and readable parameter behavior without another metadata search. The exact
formula task remained partial because its visual fallbacks did not produce an
inspectable equation; it did not reconstruct the formula from familiarity.

The consumer reported two web calls (PDF open and screenshot request) and two
browser calls (attempted PDF tab, then inventory after the timeout/reset).
The browser attempt timed out after 30.0315 seconds. No rendered PDF was
established. Incidental unrelated application metadata was not used or copied
into this record. Six read-only repository command calls were also reported.
Billed/token cost and individual web latency are unknown. Root's source priming
and ALCE cross-check used two additional web opens across this implementation.

This demonstrates one fresh task finding and applying access knowledge, plus
honest handling of an unobserved property. It does not demonstrate successful
formula recovery, repeated savings, or a general browser failure. The later
route-outage response was hypothetical: check changed conditions and remaining
budget, try justified permitted recovery, then preserve a narrower result and
the unresolved capability. No outage was manufactured or inferred.

The method update above is now persisted at the supplied owner. Its consumption
by a third task remains untested. The trial budget counted web calls but did
not set an aggregate browser/time cap; the consumer stopped after one browser
failure. This is a limitation of the trial assignment, not evidence of a fully
tested aggregate spending bound. Future multi-route trials should supply that
bound before starting, consistent with the existing resource owner.
Root consequently clarified both invocation examples and the access procedure:
name the shared time or attempt allowance, with tool-specific caps inside it.
This small wording correction received local inspection and documentation
checks; no new runtime spending test or repeated independent review is claimed.

## Verdict

The first implementation is delivered: portable rules, two callable methods,
selective routes, and fresh consumer use with explicit limits. The observed
research task resolved its bounded question; the access task reused the method
and correctly limited a partially observed result. Overall discipline
verification remains partial. There is no controlled comparison, broad
cross-model evaluation, adoption study, or completed exact-formula observation.
The earlier Grill review and autonomous-operation promise remain separate.
