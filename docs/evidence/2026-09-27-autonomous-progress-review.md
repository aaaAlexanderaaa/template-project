# Autonomous progress and independent review: delivery evidence

## Claim and scope

The [implementation plan](../plans/2026-09-27-autonomous-progress-and-review.md)
covers a refinement authorized after real autonomous use. The live owners now
require fresh direction review, meaningful candidate comparison, recoverable
multi-wake progress and inspectable evidence. This record concerns delivery of
those rules. It does not claim that an adopting scheduler enforces them or that
long-running work has improved under the new version.

## Independent historical challenge

A fresh worker received the agreed high-level purpose, source repositories,
and a read-only challenge assignment. It did not read the implementer's analysis,
implementation plan, or another review before judging. Its saved report found:

- Local reviews repeatedly approved a production direction later rejected as
  a whole. Passing usability or source checks had been promoted to evidence of
  substantive value beyond what those checks supported.
- Historical records explicitly corrected multiple earlier success reports:
  checks had failed or had not yet run when claimed. Some historical references
  also could not be resolved in the inspected checkout. This latter observation
  concerns handoff completeness; it does not prove evidence was absent on the
  original host at the time.
- Withdrawal of a rejected batch also removed still-valid revision records
  from the active data source. The archive retained them, but a later clean
  withdrawal verdict had missed the collateral effect. The implementer
  separately checked the archived and active records; no browser reproduction
  of the resulting interface effect was performed.

The worker saved its report before its task subsequently reported a credit
error. The saved findings and inspected artifacts are usable evidence; no
additional worker activity is inferred. The source experiment was not changed.
Private project names, source passages, reports and locations are retained
outside this public repository.

These findings support comparison against original purpose, actual artifact
and tool evidence, and review beyond the executor's selected changes. They
do not establish which combination of model, context, prompts and environment
caused the historical failures or prove that these revisions prevent them.

## Independent delivery review

A second fresh worker received the user's requested outcome and edited
artifacts, without the implementer's analysis or the historical review. It
assessed likely behavior in self-chosen situations before any correction
discussion. Its first consequential finding concerned the charter template:
mutable effort, alternative and progress fields were placed inside an
issuer-only authorization document. That could force ordinary strategy changes
back through the owner or leave stale execution state.

The implementer moved those fields to the existing task checkpoint, with update
authority bounded by the charter. Goal, priorities, ceilings, expiry and review
bounds remain issuer-owned. A missed progress horizon cannot be silently reset.
The same fresh reviewer re-read the corrected template, autonomy owner and
adjacent authority and review clauses. It closed the finding: normal changes of
approach can now update the task state, while due review and authorization cannot
be reset through that update. Its initial judgment remains in the private report.

The reviewer also reasoned through low-value batch production, an unavailable
due reviewer, and an ordinary local repair in an existing project. It found no
second equally supported consequential defect in that inspection. It checked
the corresponding bilingual personal documents without bringing their contents
into this repository. These observations are one document review and recheck,
not an independently operated loop or evidence of future model quality.

## Repository checks and limits

- Python 3.12 unittest suite: 118 tests, 117 passed, one skipped because the
  optional Python 3.9 command was unavailable. The fixture date was advanced to
  the current reconciliation date so copied live documents are evaluated at
  the same date as this delivery.
- Strict documentation check: 38 canonical documents and 16 templates passed.
- Whitespace check passed. The added public diff was inspected for personal
  profiles, private source locations and quotations; none are included.
- Validation used an isolated copy containing the full pre-existing working
  tree. The delivery patch is relative to that copy, preserving earlier edits.

Reproduce from the repository root with Python 3.11 or newer:

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/check_docs.py --strict
```

enforced autonomy, an adopter must exercise independent dispatch, failure to

its actual harness. No current schedule, permission, external service or source
experiment was changed. The first-party epoch-evidence promise remains open.
